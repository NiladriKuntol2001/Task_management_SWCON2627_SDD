\section{Interface and API Specifications}
The backend exposes a JSON REST API under \texttt{/api}. The full contract is written
in OpenAPI~3.0 (Swagger) in \texttt{docs/api/openapi.yaml}; \texttt{docs/api/swagger.html}
renders it as interactive Swagger UI (Figure~\ref{fig:swagger}). All endpoints except
\texttt{/health}, \texttt{/auth/register} and \texttt{/auth/login} require the header
\texttt{Authorization: Bearer <token>}, where the token is an HS256 JWT valid for 8 hours
and revoked on sign-out. The contract was checked against the running server: all 19
operations match the code, and every response in a 50-request run validated against
the documented schemas.

\paragraph{Request and response format.}
Requests and responses use \texttt{application/json}. A task is created with
\texttt{title}, \texttt{subject}, \texttt{deadline} (ISO~8601 date-time),
\texttt{difficulty} (\texttt{Easy}, \texttt{Medium}, \texttt{Hard}, \texttt{Very Hard})
and \texttt{estimated\_hours} ($0 < h \le 1000$). Each returned task carries a
\texttt{priority} object (shown \texttt{score}, \texttt{exact} score, \texttt{level},
the three component scores and their weighted parts), or \texttt{null} once completed.
Every error has the same shape, naming each invalid field and what to fix (NFR-07):

\begin{verbatim}
POST /api/tasks   {"title": "", "subject": "SWCON", "deadline": "2026-11-02T23:59:00Z",
                   "difficulty": "Hard", "estimated_hours": 0}
422  {"error": {"message": "Please fix the highlighted fields.",
                "fields": {"title": "Title can't be empty.",
                           "estimated_hours": "Estimated hours must be more than 0."}}}
\end{verbatim}

\paragraph{Main UI screens.}
The single-page frontend has these screens: sign-in/register; student dashboard
(``What should I work on today?'', counts, priority mix, upcoming); task list with
filters, search and sort; add/edit task form with live priority preview; task detail
with score breakdown; profile (change email and password); and the admin panel
(overview, users, all tasks). All screens support light and dark themes and adapt to
desktop and mobile (FR-33, FR-34).
